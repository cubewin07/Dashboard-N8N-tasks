# P07a: Character assets (base body, skeleton, animations, starter wardrobe)

Asset PR: binaries + generator scripts only. No `src/` changes except JSON content rows.

## 1. Goal and demo
Produce everything the character system (P07b) needs: a base body family with shape keys, one shared skeleton, a face atlas, one animation library, a starter wardrobe, and the **garment fitting pipeline** that makes any future clothing item fit every body slider value.
**Demo after merge:** the app looks the same (capsules still). In the PR: contact-sheet renders (`art/out/contact/*.png`, attached to the PR, not committed) show the base body at slider extremes wearing every starter item, plus a turntable GIF of the walk and sit clips. `npm run assets:check` passes.

## 2. Requirements
- **R1** A written spike decision (`art/DECISIONS.md` §"Character base") chooses between an existing CC0 base and our own generated base, with licence evidence (URL, licence text snapshot date).
- **R2** `public/assets/models/characters/body_female.glb` and `body_male.glb` exist as **separate base bodies** (boss decision 2026-11-10). They share one skeleton (identical bone names, order and rest pose) and the shape-key names `Heavy, Slim, Muscle, Chest, Hips, Shoulders`; each ≤ 3 000 tris. Topology may differ between them.
- **R3** The skeleton has ≤ 26 deforming bones, bone names matching the animation library, plus non-deforming attach bones `Attach_Head`, `Attach_HandL`, `Attach_HandR`, `Attach_Neck`, `Attach_Back`, `Attach_WristL`.
- **R4** `public/assets/textures/face_atlas.png` (512×512, 8×8 cells) holds eyes (open, half, closed, happy, per style), brows and mouths; cell map in `src/content/catalog/face-atlas.json`.
- **R5** `public/assets/anim/library.glb` holds exactly the clips listed in §3.4, skeleton-only (no mesh), ≤ 1.2 MB after optimisation; looping clips loop without a visible pop (first/last pose delta < 1° per bone).
- **R6** Starter wardrobe exported to `public/assets/models/wardrobe/`: 4 hair, 3 tops, 3 bottoms, 1 fullbody, 2 shoes, 1 glasses, 1 necklace (15 items), each within budget (garment/hair ≤ 1 500 tris), each with a `CatalogItem` row and thumbnail.
- **R7** `art/blender/fit_garment.py` transfers skin weights and all six body shape keys to a garment and passes the **clipping test**: max penetration ≤ 5 mm for every sampled slider combination inside the item's `bodyLimits`.
- **R8** Every garment declares body-hide regions; with the regions hidden, no body triangle is visible through the garment in contact sheets.
- **R9** Every file has ledger rows (`art/LICENSES.md`, `public/assets/credits.json`); `npm run assets:check` (licence + size budget) passes. Phase adds ≤ 6 MB to `public/assets`.
- **R10** Everything is reproducible: `npm run art:build -- characters` regenerates all GLBs from scripts (plus downloaded sources listed in `art/sources/characters.json`) byte-stable enough that `assets:check` passes.

### 3.2 Body family
- `body_female` and `body_male`: two separately modelled bases with clearly different proportions (shoulder/hip ratio, chest, waist, hands/feet scale), same height at rest (1.70 m; the height slider differentiates). The appearance editor shows them as "Nữ / Nam" (`AppearanceV1.base`). Both use the same skeleton, so every animation and attach bone is shared.
- Because topology differs, **each garment is fitted once per base** by the fitting pipeline and exported as `<item>_f.glb` and `<item>_m.glb`; hide masks, shape keys and `bodyLimits` are computed per base and stored per base in `<item>.meta.json`. An item may declare a single base (`bases: ['female']`, e.g. a skirt cut that only exists for one). Rigid accessories (glasses, hats, earrings) use one file for both with a per-base offset in the meta.
- Shape keys are **deltas, range 0..1 each**; `Heavy` and `Slim` are separate keys (doc `build` 0..1 maps to Slim 0.6→0 then Heavy 0→0.8, see P07b §3.3).
- Head, hands and feet are part of the body mesh; head has a flat-ish face region UV-mapped to one face-atlas cell block (eyes, brows, mouth quads are three small separate UV islands so each can switch cell independently).
- Skin colour: body UVs sit on one palette swatch (`skin_*`), remapped at assembly.

### 3.3 Skeleton (target; adapt names to the chosen library)
`Root → Hips → Spine → Spine1 → Spine2 → Neck → Head`; `Shoulder/Arm/ForeArm/Hand` L+R; `UpLeg/Leg/Foot/ToeBase` L+R; one bone per hand for fingers (`HandGrip` L+R). 24–26 deform bones. Max 4 influences per vertex. Rest pose: A-pose 45°.

### 3.4 Animation clips (`anim/library.glb`)
`idle`, `walk`, `carry_walk`, `sit_idle`, `sit_type`, `sit_read`, `sit_phone`, `stand_talk_a`, `stand_talk_b`, `wave`, `think`, `drink`, `sleep_desk`, `sleep_bed`, `sofa_sit`, `pingpong`, `arcade`, `karaoke`, `elevator_wait`, `celebrate`, `frustrated`.
- 30 fps authoring, resampled to 15 fps keys on export; loops 1–3 s; root motion removed (in-place), walk cycle tuned so foot speed = 1.3 m/s at timeScale 1 (documented in `anim/library.json` with `{clip, loop, duration, speedMps?}`).
- Seat height convention 0.45 m, desk-top 0.74 m, bed 0.40 m (must match `assets.md` furniture dimensions).

### 3.5 Garment fitting pipeline (`art/blender/fit_garment.py`, lib in `art/blender/lib/fit.py`)
Input: garment mesh authored (or generated) around one base at rest, plus the list of bases it should support. For the other base the script first re-fits the garment (shrinkwrap + smooth-corrective to that base's surface with the item's offset), then runs the same steps. Steps (per base):
1. Shrinkwrap check with offset 8 mm (tops/bottoms) or 15 mm (outer); fix inward vertices.
2. Skin weights: Data Transfer (nearest face interpolated) from body, limit 4, normalise, smooth 2 iterations.
3. For each body shape key : bind garment with Surface Deform to the body, set key to 1, bake garment deformation as a garment shape key of the same name.
4. **Clipping test:** sample slider combos (corners of the 6-D box + 20 random, both bases); for each, ray-cast garment vertices inward to the deformed body; report max penetration. If > 5 mm, shrink the offending slider's range in 0.05 steps until it passes → write `bodyLimits`.
5. Hide masks: body faces whose every vertex is > 6 mm under the garment at rest and at all tested combos → vertex group `hide_<item>`; exported as a triangle-index range list in `<item>.meta.json` (body is exported with faces sorted by region so ranges are compact).
6. Export GLB (skinned, morph targets, `M_Palette`, tint regions as vertex colour channel `TINT`: R=primary, G=secondary, B=accent mask).
7. Emit `art/out/reports/<item>.json` {tris, maxPenetrationMm, bodyLimits, hideRanges, bytes}.

Skinned vs rigid: hair, glasses, necklace are **rigid** (parented to an attach bone, no morphs) unless long hair reaches the shoulders (then skinned to Head/Neck/Spine2 with no shape keys but an offset rule from `Shoulders`).

## 4. Design choices
| Topic | Options | Choice | Reason | Revisit if |
|---|---|---|---|---|
| Base body | CC0 pack as-is · own generated body · AI-generated mesh | **Own body (default), CC0 rig/animations reused** | Continuous sliders need controlled shape keys on body *and* clothes; packs have baked clothes | Spike finds a CC0 pack with separable clothes + shape keys |
| Body sliders | bone scaling only · shape keys · both | **Shape keys for build; bone/root scale only for height** | Bone scaling breaks animation contact (hands on desk); shape keys keep the skeleton constant | Morph count hurts perf (see `performance.md`) → bake morphs at assembly (already planned in P07b) |
| Clothes fit | per-size variants · runtime cloth · transferred shape keys | **Transferred shape keys + clipping test + hide masks** | Fully scriptable; zero runtime cost after assembly | Penetration cannot get under 5 mm for loose items → allow per-item extra offset |
| Face | geometry features · texture atlas cells | **Atlas cells** | Many faces for few bytes; gives blink/sleep for free | Close-up wardrobe view looks too flat → add nose geometry variants |
| Two silhouettes | one · two (a/b) · many | **Two sharing topology** | Variety without doubling garment work | – |
| Animations | Mixamo · UAL CC0 · hand-authored | **UAL (verify) else authored in script** | Mixamo raw files are not redistributable in a public repo | – |

**Decisions added while finishing the phase (2026-11-14).**

| ID | Topic | Choice | Reason | Revisit if |
|---|---|---|---|---|
| D-P07a-1 | Garment per base | Skinned items ship as `<id>_f.glb` / `<id>_m.glb` with one `<id>.meta.json` holding per-base `file`, `tris`, `hideRegions`, `bodyLimits`, `maxPenetrationMm`; the dress ships female-only | Topology differs between bases, so each base gets its own fitted copy; one meta keeps the catalogue row simple | Wardrobe bytes approach the 15 MB budget → share one garment and refit at load |
| D-P07a-2 | Layering | Tops flare at the hem (offset ≈ 23 mm) and bottoms tuck their waistband (≈ 10 mm), so a top always covers a bottom | Avoids waistband triangles poking through hems at slider extremes without a runtime layer system | Layered jackets arrive (P08a) → add an explicit layer index |
| D-P07a-3 | Hide masks | `lib/fit.py` hides a body region only if the garment covers all of it at Basis and at every slider extreme inside `bodyLimits` | Animated poses (walk, sit) showed skin through shoulders and thigh creases with hand-picked masks; partial regions stay visible so no holes appear | Region granularity too coarse for new items → split regions in `gen_body.py` |
| D-P07a-6 | Female ease | Female tops and the dress get extra ease at bust and belly that grows with the transferred `Heavy`/`Chest` deltas, so every starter garment covers the full slider range (`bodyLimits: {}`) | With narrowed limits a heavy female employee had no top or dress at all | A future tight-fit item cannot reach 5 mm → narrow its `bodyLimits`, but never leave a slot with no full-range item |
| D-P07a-5 | Joint order in `library.glb` | Accept the exporter's depth-first joint order in the skeleton-only library; bodies and garments keep `art/rig.json` order | Names and rest pose are identical everywhere and three.js binds clips to bones by name, never by skin index | P07b binds tracks by index → re-export with `rig.json` order |
| D-P07a-4 | Face quads | Eye, brow and mouth patches are placed 1.75 mm in front of the finished skin (BVH), split on head facet ridges | The earlier formula put the mouth inside the skin and brows up to 18 mm off the face | – |

## 9. Risks and open questions
- **Retargeting quality** from UAL to our rig may look off for seated clips → fallback: author seated clips in script (few bones move).
- **Surface Deform bake** can fail on non-manifold garments → pipeline falls back to nearest-surface delta transfer; documented in `lib/fit.py`.
- **Skirts** are deferred to P08a (needs a leg-blend strategy).
- Hands with one grip bone limit prop holding poses; acceptable for low-poly.
- Separate male/female bases (decided) double fitting runs and garment bytes. Mitigation: fitting is scripted per base, the clipping test runs per base, and the wardrobe budget is 15 MB (`00-overview.md` §7). If cross-base re-fitting of a garment fails the clipping test, the item ships single-base.
