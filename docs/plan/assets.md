# Assets: style, sourcing, pipeline, budgets

Shared rules for every 3D asset (environment P06a, characters P07a, wardrobe P08a). Phase files reference sections here by number. Changing §1 (style/scale/palette/skeleton conventions) after P07a is **expensive**: every model depends on it.

## 1. Style guide

**Look:** low-poly, flat-shaded, a few bevels on the edges people notice (desk tops, chair seats, screens). "Simple but detailed enough to feel real": every object has 2–4 recognisable sub-shapes (a desk has a top, legs, a drawer block, a cable tray), never a single box, never photoreal. Soft warm lighting; no textures except the palette; no outlines.

### 1.1 Units and axes
- Metres. +Y up. The building's **front (cutaway) faces −Z**. An object's "front" (where a person stands/sits to use it) faces **−Z in its own space** at `rotY = 0`.
- glTF export: +Y up, apply transforms, scale 1.0. No negative scales. No parenting chains deeper than 2 for static props.
- Reference sizes: floor height 4.0 m (slab 0.3 + clear 3.7); desk top 0.74 m high, 1.4 × 0.7 m; chair seat 0.46 m; door 2.1 × 0.9 m; elevator car 2.0 × 2.0 × 2.6 m; stair width 1.2 m; nav grid cell 0.5 m, so footprints snap to 0.5 m where possible.
- **Character base height 1.70 m** (neutral body sliders), slightly stylised: head ≈ 1/6.5 of height, slightly large hands and feet, simplified fingers (mitten + thumb). Same body for everyone; variety comes from sliders and wardrobe.

### 1.2 Palette
- One texture: `public/assets/textures/palette.png`, **256 × 256, 16 × 16 grid of 16 px swatches**, nearest filtering, no mipmaps, sRGB. Generated by `art/blender/gen_palette.py` from `src/content/palette.json` (source of truth). Never hand-edited.
- `palette.json`: `{ "version": 1, "cell": 16, "swatches": [{ "key": "jade_600", "hex": "#0F766E", "row": 2, "col": 5, "group": "accent" }, …] }`. A swatch's `row,col` is **stable forever** (append only): models bake UVs to cells.
- Rows (0-based):

| Rows | Group | Contents |
|---|---|---|
| 0–1 | `neutral` | Warm neutrals from the UI tokens: `#FAF9F7` → `#1C1B19` in 16 steps, plus warm greys for concrete/metal |
| 2 | `accent` | Jade ramp (`jade_100`…`jade_900`, UI primary `#0F766E` = `jade_600`), status colours (working blue, waiting amber, blocked red, done green, idle grey) each light + base |
| 3 | `dept` | Department swatches (`dept_cs`, `dept_marketing`, `dept_design`, `dept_accounting`) light/base/dark + 4 spare triplets for future departments |
| 4–5 | `wood_fabric_env` | Woods (4 ramps × 4), upholstery, carpet, plant greens, terracotta, paper white/cream, cardboard |
| 6 | `metal_screen` | Steel, chrome, black plastic, screen off/on bases |
| 7–8 | `skin` | `skin_01`…`skin_08`, each with base + shadow + blush + lip (32 cells) |
| 9 | `hair` | `hair_black`, `hair_brown_dark`, `hair_brown`, `hair_chestnut`, `hair_blonde`, `hair_grey`, `hair_white`, + 4 fashion colours, each base + highlight |
| 10–13 | `fabric` | Wardrobe fabric swatches `c_*` (white, black, greys, navy, denim ×3, khaki, jade, red, pink, yellow, orange, purple, pastel set…), each base + shade (up to 32 colours) |
| 14 | `eyes_misc` | Eye colours, teeth, gold, silver, pearl, gem colours |
| 15 | `reserved` | Empty; future use |

- **UV rule:** every face's UVs sit inside one swatch cell (shrunk 2 px from the cell edge to avoid bleed). `art/blender/lib/palette.py` provides `paint(obj, face_selector, "swatch_key")`.
- **Tintable regions** (wardrobe, some furniture): instead of a fixed swatch, faces carry a vertex-colour marker in the `TINT` attribute (R=1 primary, G=1 secondary, B=1 accent). The runtime replaces their colour with a chosen swatch (P07b decides bake-at-assembly vs uniform). Untinted faces have `TINT = 0`.

### 1.3 Materials
Only three, shared by name across all GLBs so the runtime can replace them with singletons:

| Name | Use | Notes |
|---|---|---|
| `M_Palette` | everything opaque | baseColorTexture = palette, roughness 0.85, metallic 0, flat shading via split normals |
| `M_Glass` | windows, office walls, aquarium | baseColor from palette, alpha 0.25, roughness 0.1; `alphaMode: BLEND`; never on characters |
| `M_Emissive` | screens, lamps, indicator lights, elevator display | emissive; runtime drives colour/intensity by mesh name suffix `_screen`, `_lamp`, `_led` |

`assets:check` fails any GLB with another material, an embedded texture other than the palette, or more than one UV set.

### 1.4 Poly budgets (triangles, after export)

| Asset | Max tris |
|---|---|
| Small prop (phone, cup, paper, folder) | 150 |
| Furniture item (chair, monitor, plant, cabinet) | 1 000 |
| Large set piece (boss desk set, reception counter, karaoke corner, elevator car) | 3 000 |

| Character body (base, with shape keys) | 3 000 |
| Garment | 1 500 |
| Hair | 1 500 |
| Accessory | 400 |
| **Assembled character** | **8 000** |

### 1.5 Naming and pivots
- File: `category_name_variant.glb`, lowercase snake_case, 2-digit variant: `desk_standard_01.glb`, `chair_office_02.glb`, `plant_monstera_01.glb`, `top_tshirt_crew_01.glb`. One object per file unless it is a *set* (`set_boss_lounge_01.glb`).
- Root node name = file name without extension. Sub-meshes that the runtime addresses use suffixes: `_screen`, `_lamp`, `_led`, `_door_l`, `_door_r`, `_seat` (empty: sit anchor), `_stand` (empty: stand-to-use anchor), `_pile` (empty: paper pile anchor), `_hand_r` (empty on held props: grip point).
- **Pivot:** at the floor, centre of footprint (X/Z), Y = 0. Wall-mounted items: pivot on the wall plane at mount height centre. Held props: pivot at the grip. Wardrobe: pivot at the character origin (between the feet); skinned to the shared skeleton (`phase-07a`).
- Anchors are glTF empty nodes; `scripts/assets-manifest.mjs` extracts them into `public/assets/manifest.json` (`{ file, tris, bytes, bbox, footprint, anchors }`) so layout code never parses GLBs to find seats.

## 2. Sourcing

### 2.1 Order of preference
1. **Existing CC0 packs**, restyled onto the palette (fast, consistent author style per pack).
2. **CC0 single models**, then **CC-BY 4.0** single models (credit required).
3. **Generate in Blender** from Python (always possible for furniture/architecture; the fallback for everything).
4. AI-generated models: **allowed** (boss decision, 2026-11-11). This covers generator scripts written by a coding agent (the default, see 3) and text/image-to-3D tools such as Blender MCP `generate_3d`. The output licence must be checked and recorded like any other asset, and the result must pass the same palette, budget and `assets:check` rules. A tool that costs credits is still announced before a batch is run.

### 2.2 Candidate sources (every one must be VERIFIED at download time)
The licence and download method below are what we expect; the downloading agent confirms on the source page and records the evidence (URL + date + licence text snippet) in `art/sources/manifest.json`. If a pack's licence is not what is expected, skip it and fall back.

| Source | Expected licence | Candidate packs | Use for |
|---|---|---|---|
| Kenney (kenney.nl) | CC0 | Furniture Kit, City Kit (commercial/suburban), Mini Characters / Blocky Characters (reference only) | furniture, building bits, street context |
| Quaternius (quaternius.com) | CC0 | Ultimate Modular Men / Women, Universal Animation Library, furniture/office/interior packs | character base + clothing reference, **animations**, furniture |
| KayKit (Kay Lousberg) | CC0 | Furniture Bits, Restaurant Bits, character packs | furniture, café items, games props |
| Poly Pizza (poly.pizza) | per model: CC0 or CC-BY | single models (cat, arcade, ping-pong, aquarium) | gaps |
| Poly Haven | CC0 | HDRIs (1k), a few props | lighting environment |
| Sketchfab | per model; **CC0 / CC-BY only, "downloadable" only** | single models | last external resort |
| Google Fonts | OFL | Be Vietnam Pro TTF | 3D text |

**Not allowed:** CC-NC, CC-ND, CC-SA, "free for personal use", unknown/unstated licence, raw Mixamo files (redistribution in a public repo is not permitted), anything extracted from a game or a paid pack, real brand logos as 3D assets or textures.

### 2.3 How agents get assets without the human
Try in this order, per pack:
1. **Direct HTTP**: `node scripts/assets-fetch.mjs <sourceKey>` reads `art/sources/manifest.json`, downloads to `art/.cache/<sourceKey>/`, verifies `sha256` (first download records it), unzips. Works for kenney.nl and Poly Haven direct links and for Poly Pizza / Sketchfab API downloads.
2. **Blender MCP** (only when a Blender session with the addon is open): `search_assets` → `import_asset` (Poly Haven, Sketchfab, Poly Pizza), `look` for visual QA. The agent then runs the same normalise/remap functions and exports through the standard export path. Record the asset id and licence in the manifest exactly like a direct download.
3. **Browser automation** (click-through pages such as itch.io "No thanks, just take me to the downloads"): use the browser automation skill, save the zip into `art/.cache/<sourceKey>/`.
4. **If all three fail:** append an entry to `art/MANUAL-DOWNLOADS.md`: pack name, exact URL, expected file name, licence, and "drop the zip in `art/.cache/<sourceKey>/`". Then continue with a Blender-generated substitute so the phase is not blocked. This is the **only** manual asset step in the whole plan.

`art/sources/manifest.json` entry:
```json
{ "key": "kenney_furniture_kit", "name": "Furniture Kit", "author": "Kenney", "url": "https://kenney.nl/assets/furniture-kit",
  "downloadUrl": "…zip", "method": "http", "sha256": "…", "licence": "CC0-1.0",
  "licenceEvidence": "page text: 'License: Creative Commons CC0'", "retrievedAt": "2026-11-…", "retrievedBy": "agent" }
```
Downloaded archives are **never committed** (cache is git-ignored); only the processed GLBs are.

## 3. Blender pipeline

- Binary: `/Applications/Blender.app/Contents/MacOS/Blender`. P06a-T01 verifies `--version` ≥ 4.2 and writes the exact version to `art/STYLE-GUIDE.md`. Override with env `BLENDER_BIN`.
- All work is **headless and scripted**: `"$BLENDER_BIN" -b --factory-startup -P art/blender/gen_desk.py -- --out public/assets/models/props`. Generator scripts are the source of truth; **no `.blend` files are committed**. Scripts are deterministic (fixed seeds, no time-dependent names).
- Shared library `art/blender/lib/`:

| Module | Provides |
|---|---|
| `palette.py` | load `palette.json`; `paint(obj, faces, key)`; `tint_mark(obj, faces, 'primary')`; `nearest_swatch(rgb, group=None)`; create `M_Palette`/`M_Glass`/`M_Emissive` |
| `mesh.py` | primitives with bevel helpers, `flat_shade`, `add_anchor(name, loc, rot)`, boolean-free panel/leg/drawer builders, `tri_count` |
| `normalise.py` | apply transforms, set pivot (floor-centre / wall / grip), scale to a target dimension, snap footprint to 0.5 m, rename by convention |
| `remap.py` | for imported packs: bake each foreign material's base colour (or dominant texture colour per face) to the nearest palette swatch, drop textures, merge to `M_Palette`; decimate/limited-dissolve to budget |
| `export.py` | glTF binary export with fixed settings (+Y up, no cameras/lights, apply modifiers, tangents off, vertex colours `TINT` only where used, shape keys + skin when present) |
| `render.py` | Workbench/EEVEE thumbnail and contact-sheet rendering with a fixed 3/4 camera and neutral light |

- npm scripts (added in P06a-T02):

| Script | Does |
|---|---|
| `art:build [-- <target>]` | runs generators/importers (`all`, a family, or one asset); writes raw GLBs to `art/.cache/raw/` |
| `assets:optimize` | `@gltf-transform`: `dedup`, `prune`, `weld`, `quantize`, `meshopt` (**no Draco**: meshopt decodes faster and needs no wasm worker setup beyond the small decoder); writes to `public/assets/models/**` |
| `assets:manifest` | rebuilds `public/assets/manifest.json` (tris, bytes, bbox, anchors) |
| `assets:check` | fails on: file without licence row; over size budget (§6); bad name; over tri budget; non-palette material/texture; missing required anchors per category; orphan credits rows |
| `thumbs:render` | wardrobe item thumbnails (P08a) and contact sheets |
| `assets:all` | build → optimize → manifest → check |

- Visual QA: each asset PR includes contact sheets `art/out/contact-sheet-*.png` (committed, ≤ 400 KB each) rendered headless, so reviewers do not need Blender.

## 4. Consistency across mixed sources
1. Everything passes through `remap.py` → one palette, one material. This is what makes Kenney + Quaternius + generated items look like one set.
2. Scale check: every imported item is resized to §1.1 reference sizes by category (a chair seat is 0.46 m regardless of pack).
3. Bevel/detail level: items much more detailed than their neighbours get a limited dissolve; items that are bare boxes get rejected in review (regenerate with sub-shapes).
4. The contact sheet shows all items of a family side by side on the same floor grid with a 1.70 m character silhouette; the reviewer checks "could these be from one pack?".

## 5. Licence ledger
- `public/assets/credits.json` (machine, shipped): `{ "<creditKey>": { "title", "author", "source", "url", "licence": "CC0-1.0" | "CC-BY-4.0" | "OFL-1.1" | "own-CC0", "modified": true, "files": ["models/props/chair_office_01.glb"] } }`. Generated assets use `own-CC0` with author "AI Office project".
- `art/LICENSES.md` (human): the same as a table, grouped by source, plus the licence texts/links and the retrieval date.
- Every file under `public/assets/**` (except `manifest.json`, `credits.json`) must be listed in exactly one credit's `files`. `scripts/licences-check.mjs` enforces it in CI.
- **In-app credits page** (P06b-T11): `#/credits`, linked from Settings, lists `credits.json` grouped by author with links. Required by CC-BY and good manners for CC0.

## 6. Size budgets (enforced by `assets:check` / `scripts/size-budget.mjs`)

| Item | Budget |
|---|---|

| `models/env` + `props` + `decor` (P06a) | ≤ 8 MB |
| `models/characters` + `anim/library.glb` (P07a) | ≤ 6 MB |
| `models/wardrobe` + `thumbs` (P08a) | ≤ 15 MB (garments per base) |
| Single GLB | ≤ 1.5 MB (typical < 300 KB; furniture typically < 60 KB) |
| Thumbnail (256 px webp) | ≤ 15 KB |
| HDRI (1k, .hdr or .exr → prefiltered) | ≤ 1.5 MB |
| Contact sheet PNG (in `art/out/`) | ≤ 400 KB each |

No Git LFS (`stacked-prs.md` §3). Revisit at 30 MB.

## 7. What the human must do
**By default: nothing.** Possible exceptions, each surfaced explicitly by the agent:
1. Resolve entries in `art/MANUAL-DOWNLOADS.md` (click a link, drop a zip in a folder). Expected: zero to three entries in total.
2. Optionally open Blender with the MCP addon during an asset session so the agent can use `look` for interactive visual QA (headless contact sheets are the default and need nothing).
3. Approve or decline AI generation for a specific item if an agent asks (default answer assumed: no).
4. Look at the contact sheets in the asset PRs and say "I like / don't like the style" (taste check, 5 minutes per asset PR).
